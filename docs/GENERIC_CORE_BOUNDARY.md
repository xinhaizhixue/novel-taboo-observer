# 工具层通用性边界

## 硬约束

产品核心必须能打开不同题材、不同作者、不同目录组织的 Markdown/TXT 小说 Git 仓库。核心运行时不得认识某一本作品的作品名、人物名、卷号、世界观术语、固定仓库路径或专属创作流程。

## 三层

1. `src/`、`electron/`：通用产品核心。只处理项目清单、文本文件、事件、目标、任务、事实、评论、作者档案、Agent、权限、恢复和 Git 等抽象能力。
2. 小说 Git 仓库：保存作品名、题材、人物、正典、卷章、规划、决策、研究、角色说明和事件流。换作品时替换这一层，不修改产品核心。
3. `scripts/`、`workspaces/`：端到端验收夹具和真实长期试写项目。可以包含专用剧情与迁移脚本，但删除它们不得影响工作台启动、打开其他项目或使用核心功能。

## 发布门

`npm run audit:generic` 扫描 `src/` 与 `electron/`：

- 禁止真实验收项目专有标识进入核心；
- 禁止核心导入 `scripts/` 下的验收脚本；
- 禁止核心写死 `workspaces/<project>` 路径。

该审计已接入 `npm run check`。新增题材模板或项目专用自动化时，应放在项目数据、模板或验收层，并通过通用协议调用核心能力。
