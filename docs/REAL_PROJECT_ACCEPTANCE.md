# 真实作品功能验收矩阵

## 目的

本矩阵用于证明“平台真实可用且所有功能都用过”，避免把以下证据混为一谈：

- `verified-real`：在《万劫铸身》仓库或真实桌面环境留下可回读证据。
- `verified-automated`：自动化测试覆盖，但尚无真实作品/真机操作证据。
- `partial`：闭环的一部分已有真实证据，关键步骤仍缺。
- `pending`：没有足够证据。

只要存在非`verified-real`项，完整目标就不能标记完成。

## V2 完成性纠正（2026-08-24）

此前 23/23 全绿仍被真实用户快速发现以下缺口，因此旧矩阵不能继续作为“平台完成”的充分证据：项目打开后无法新建小说、仓库路径/remote 不可见、章节/卷/整仓无安全删除；Git 页直接展示原始 patch/JSON；全局正文颜色被启动占位样式污染；风格档案没有从仓库快照恢复且缺少编辑/删除；评论/Agent 左右重复导航；没有用户指南与首次引导。

最终验收新增六项硬门：

1. `project-lifecycle-v2`：作品中心、新建/打开、仓库信息、章节/卷软删除与恢复、整仓系统废纸篓；
2. `content-lifecycle-v3`：正文、大纲、研究、人物与世界、决定、嵌套目录和系列单部作品全部具备统一软删除/恢复；结构化记录使用可审计状态语义；
3. `human-git-diff-v2`：成熟 Diff 组件、行号、增删色、split/unified、系统事件摘要；
4. `author-style`：真实记忆整理员产生多证据候选，规则可确认、编辑和删除；
5. `information-architecture-v2`：评论和 Agent 不再占用重复左侧空页面；
6. `user-guidance-v2`：首次引导、页面内帮助和完整作者指南；
7. `visual-contrast-v2`：10 个主页面、关键弹窗和用户三张截图场景的运行时对比度回归。

只有新项也成为 `verified-real` 后，才允许再次讨论平台是否完成。

## V2 实际验收结果（2026-08-24 22:54，Asia/Shanghai）

V2 回执 `usability-lifecycle-v2` 已由真实 macOS Electron 操作写入作品事件流，六项新增硬门均为 `verified-real`：

- 从已打开的《万劫铸身》进入作品中心，在专用空目录建立《生命周期UI验收》，真实完成第一章建卷、第二章新建、整卷影响预览、软删除、恢复，以及整仓移入 macOS 废纸篓；真实小说仓库未执行删除。
- 作品中心真实显示绝对路径、分支、HEAD、remote 状态、Finder 和复制路径入口；整仓删除要求输入作品名，产品不提供永久清空废纸篓操作。
- 正文差异真实验证统一/并排视图、行号和增删色；`.novel/events/*.jsonl` 默认翻译为作者可读的任务、Agent 与风格档案记录，同时保留原始差异入口。
- 记忆整理员经工作台真实运行并完成，形成 8 条、每条 3～4 份证据的候选；随后在 UI 精炼一条候选、删除一条与既有规则重复的候选。当前仓库快照共 9 条规则：2 条已确认、7 条待确认，证据与状态可迁移。
- 左侧不再出现评论/Agent 重复空页面；右侧面板、首次四步引导、完整帮助页和普通作者指南均在 Electron 中可见。
- 10 个主页面与 9 类关键弹窗运行时对比度扫描为 0 项违规；新建小说、删除影响、风格档案、正文 Diff、系统事件、项目设置和帮助页均完成真实 Electron 截图回归。
- 长正文重新执行章首 → 章尾 → 章首滚动，滚动条可见、中文排版和正文内边距正常。

最终 live 结果：`npm run audit:features` 为 **28/28 verified-real、0 automated-only、0 partial、0 pending**；`npm run check` 通过 **19 个测试文件、56 项测试、类型检查、生产构建和通用性硬门**。验收没有创建 Git commit，也没有继续扩写小说。

## V3 删除覆盖纠正（2026-08-25）

作者再次推翻上面的“完成”结论：V2 只验证了正文章节、整卷和整仓，遗漏大纲、研究、人物与世界、决定、嵌套目录及系列单部作品。该遗漏说明生命周期验收必须先枚举全部对象类型，不能等作者逐项指出后局部补按钮。V2 回执保留为历史证据，但不能单独证明完整删除能力；只有新的 `content-lifecycle-v3` 通过真实 Electron 全对象矩阵后，才能重新恢复完成结论。

## 执行

开发阶段查看：

```bash
FEATURE_ALLOW_INCOMPLETE=1 npm run audit:features -- workspaces/wan-jie-zhu-shen
```

最终验收：

```bash
npm run audit:features -- workspaces/wan-jie-zhu-shen
```

最终命令默认在任何自动化-only、partial或pending项目存在时返回非零。它必须与以下证据一起使用：

```bash
npm run check
NOVEL_ALLOW_INCOMPLETE=1 npm run audit:novel -- workspaces/wan-jie-zhu-shen
```

小说审计用于证明平台经历过足够长的真实作品压力，不是要求把验收小说写完。平台完成以本矩阵全部成为 `verified-real`、`npm run check` 通过且真实 UI 无关键缺口为准；小说达到目标字数既不是必要条件，也不能替代平台验收。只有新章节能覆盖尚未验证的能力时才继续写。

## 权威范围

矩阵以`docs/PRODUCT_REQUIREMENTS_V0.2.md`第20～21节为功能与不变量基线，以live产品代码、测试输出、小说Git仓库、事件流和真机结果为证据。Business Wiki和历史助手摘要只能用于定位，不可替代live证据。

## 持续回归必须保留的证据

下列历史高风险路径当前已经有真实证据，但后续改动仍必须持续回归：

1. 真实小说内的Agent Writer任务、Agent Observer任务与Navigator路线提案，而非仅自动化夹具。
2. Writer停止/中断后不重跑、未保存缓冲拦截与Git diff审查的真实桌面闭环。
3. Claude Code第二适配器真任务，或在未安装环境下的明确UI降级。
4. 真实系列仓库、TXT章节、恢复快照和全新clone读回。
5. macOS Electron交通灯、全页面点击和黑屏回归。

## 历史事件膨胀说明

早期百万字迁移脚本曾重复追加相同`project.position`。当前脚本已按`filePath/stage/focus`幂等，历史事件保持append-only不删除；审计输出总数、唯一数和历史重复行，防止它被误认成当前仍在重复。后续若需要压缩，只能通过显式版本迁移与保留原始证据完成，不能直接改写历史JSONL。
