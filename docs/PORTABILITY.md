# 跨电脑、备份与恢复

## 换电脑继续写

1. 在旧电脑检查 Git 变更。只有已经 commit 并同步到远端的内容会随普通 clone 到达新电脑；也可以完整复制未提交的仓库目录。
2. 如果使用作者级风格规则，在“风格与能力”页导出作者档案 JSON。
3. 新电脑安装本工作台、Git 和至少一个通用 Agent，并在 Agent 自己的客户端完成登录。
4. clone/复制小说仓库，用工作台打开仓库。工作台读取 manifest、重放 JSONL 事件并重建目标、任务、评论、故事事实和 Agent 摘要。
5. 需要时导入作者档案。不要复制 API Key、Token 或 Agent 登录目录。

仓库中的正文、正典、规划、决定、目标、任务、重要评论/反馈和 Agent 任务摘要可以恢复。全文索引、界面布局、完整终端日志和本机崩溃恢复点默认不迁移。

## 未提交内容

Git clone 不会带走未提交内容。迁移前应在“Git 变更”页审查并明确提交，或完整复制整个小说工作目录。工作台不会为了迁移擅自 stage、commit 或 push。

## 崩溃恢复

有未保存变化时，工作台默认最多每 30 秒在 Electron userData 下保存一个去重恢复点；窗口失焦、冲突处理和应用退出前还会额外保存。打开文件后若发现比磁盘更新的恢复点，会自动打开恢复列表。

恢复操作只把内容放回未保存缓冲区。作者检查后再点击保存；恢复本身不会改变磁盘文件或创建 Git 提交。

## 数据版本

`.novel/manifest.json` 包含 `schemaVersion`。当前版本为 1：

- 版本一致：直接打开并重建状态；
- 仓库版本更高：拒绝写入，提示升级工作台；
- 未来低版本升级：必须先备份，再由显式迁移器转换，不能让 Agent 自由改写历史事件。
