# 禁忌观察者 UI 设计与验收规范

## 目标

工作台面向长时间阅读中文正文的作者。视觉设计优先保证信息层级、可读性、低干扰和操作可恢复，不使用“浅色即高级”作为降低对比度的理由。

参考交互模式：GitHub/GitLab 的文件差异、VS Code/GitHub Desktop 的仓库状态、成熟写作软件的纸张阅读区与非阻塞侧栏。

## 颜色令牌

定义在 `src/styles.css :root`：

- `--ink`：正文和标题；
- `--muted`：说明、时间、元数据，仍须满足普通文字 4.5:1；
- `--paper`：主内容底色；
- `--panel`：文件树和侧栏底色；
- `--accent`：主动作，搭配浅色文字须满足 4.5:1；
- `--accent-2`：文字链接与次级强调；
- `--danger`：删除和阻塞；
- `--sage`：完成与安全状态。

启动占位页的浅色文字只能作用于 `.boot-screen`，不能把 `body` 的真实应用文字设置成浅色。

## 对比度门禁

- 普通文字：WCAG AA `>= 4.5:1`；
- 18px 以上或 14px 粗体：`>= 3:1`；
- 禁用控件可以弱化，但文字和轮廓不能消失；
- hover/focus/selected 不只依赖颜色，须同时有背景、边框或图标变化；
- 每次改全局布局后运行 `tests/contrast.test.ts`，并用浏览器计算样式扫描全部主页面和关键弹窗。

## 信息架构

- 左侧主导航只放会占据中央工作区的页面；
- 评论、Agent、上下文属于同一个右侧辅助面板，不在左侧建立重复空页面；
- 底部 Agent/Observer 状态可点击，负责重新打开右栏；
- 作品标题旁的“作品与仓库”负责新建、打开、路径、remote、回收站和整仓操作；
- 高风险弹窗只用于删除、冲突、提交和正典确认。

## Git 差异

- 正文使用 `@git-diff-view/react`，默认 unified，可切换 split；
- 必须展示行号、增删颜色、文件状态和说明；
- `.novel/events/*.jsonl` 默认转换为任务、评论、Agent、文件保存等事件卡片；
- 原始 JSON 始终可展开审计，但不能作为默认作者界面；
- 保存与提交严格分离，提交弹窗明确列出文件。

## 删除

- 章节/卷：先分析文件数、字数、事实、任务和评论引用，再移入仓库外工作台回收站；
- 恢复时不覆盖同名新内容；
- 整仓：只调用 macOS 废纸篓，不提供永久删除；
- 删除不会自动 Git commit。

## 真机回归

至少覆盖：继续创作、旅程、正文、规划、人物世界、任务、Git、风格、设置、帮助；以及新建文件、作品中心、新建小说、任务编辑、风格编辑/删除、正典影响、Git 提交、章节/卷删除和冲突弹窗。
