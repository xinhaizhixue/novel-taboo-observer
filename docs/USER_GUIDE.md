# 禁忌观察者：作者使用指南

这是一套本地长篇小说写作工作台。一本独立小说或一个系列对应一个 Git 仓库；正文、正典、规划和重要创作记录由你控制，Codex CLI、Claude Code 等通用 Agent 负责可以交给 AI 的劳动。

## 1. 第一次打开

开发环境运行：

```bash
npm run dev
```

真实写作使用自动打开的 Electron 窗口。`npm run dev:web` 只是浏览器 UI 演示，不会读取仓库、运行 Agent 或操作 Git。

如果 Agent 提示所选模型需要更新的 Codex 版本，可以升级 CLI，或指定本机已经安装的新版程序。macOS 安装了 Codex 桌面应用时，可使用：

```bash
NOVEL_OBSERVER_CODEX_PATH=/Applications/Codex.app/Contents/Resources/codex npm run dev
```

在右侧 Agent 面板核对显示的版本与登录状态，再重试原任务；工作台不会自动换模型或重复写正文。

## 2. 从头新建一篇小说

无论是否已经打开其他作品，都可以点击左侧作品标题右侧的“作品与仓库”按钮：

1. 点击“新建小说”。
2. 选择“独立小说”或“系列作品”。
3. 填写作品名、一句话灵感和计划篇幅；暂时没有灵感也可以留空。
4. 选择一个空目录作为仓库位置。
5. 点击“建立写作现场”。

工作台会创建 Git 仓库、第一章、故事正典、作品风格、滚动规划、研究目录、确认决定、初始目标与任务。创建完成后，“继续创作”页的新手引导会带你走过故事方向、第一段正文、Observer 审查和 Git 检查。

已有 Markdown/TXT 小说可以点击“打开其他仓库”。首次打开普通 Git 仓库时，工作台会补充 `.novel` 项目标识和标准目录，但不会改写已有正文。

## 3. 界面怎么分工

- **左侧主导航**：继续创作、创作旅程、正文、规划、人物与世界、任务、Git、风格、设置和帮助。
- **左侧文件树**：章节、分卷、规划、研究、正典和决定。
- **中间**：正文编辑器或当前功能页面，是主要工作区域。
- **右侧**：评论、Agent 会话和本次上下文。评论与 Agent 不在左侧重复出现。
- **底部状态栏**：保存状态、Git 分支和改动数、Agent/Observer 状态、字数。Agent 和 Observer 状态可点击打开右栏。

## 4. 日常写作流程

1. 在“继续创作”确认当前位置、当前目标和最多三个下一步。
2. 点击“继续写作”自己编辑，或者“交给 Writer”。
3. 自己写作时可主动开启右侧 Observer；它只分析不可变快照，不直接改正文。
4. 对评论选择接受、拒绝、暂缓、有意保留、要求解释或修改后复查。拒绝、暂缓和有意保留均可附上理由；取消对话框不会改变评论。已拒绝或有意保留的历史评论也能补充理由。最新作者反馈会随作品上下文提供给后续 Agent，不会自动升级为跨作品的风格规则，也不代表模型已完成训练。

Observer 审读期间可以继续在工作台保存正文、新建章节或重命名文本文件。工作台用本次进程内的操作回执及实际内容核对来源，这些变化会单独显示为“同期作者编辑”，不记成 Agent 越权。只有仓库事件自称“作者写入”不算证明；来源不明或保存后又被外部程序改动的文件仍会提示核查。该机制不会解除 Writer 对正在改写正文的占用，也不放宽删除操作的既有保护。
5. 到“Git 变更”查看这一批实际增加、删除和修改了什么。
6. 只有准备好时才点击“明确提交”。保存文件从不等于 Git 提交。

在右侧 Agent 任务框中可以按 `Command/Ctrl + Enter` 开始任务；启动前仍应检查角色、修改范围和本次上下文。

## 5. Agent 角色

| 角色 | 适合交付 | 是否直接改文件 |
|---|---|---|
| Writer | 续写、重写、扩写、压缩、润色 | 只改明确授权的正文范围 |
| Observer | 连续性、因果、节奏、知识边界和风格评论 | 否 |
| Navigator | 判断阶段、安排下一步、生成路线候选 | 否 |
| Story Architect | 卡文诊断与多路线推演 | 否 |
| Canon Keeper | 设定、时间线、人物知识边界核查 | 否 |
| Researcher | 来源化考据 | 只写授权的 `research/` |
| Editor | 结构审校与全书修订建议 | 否 |
| Release Assistant | 标题、简介、标签和发布检查 | 否，不自动发布 |
| 记忆整理员 | 从多条正文和反馈证据中提炼风格候选 | 否 |

Agent 不得执行 Git 写操作。联网只对单次 Researcher 任务授权，不形成永久权限。

## 6. 写作风格与能力

“风格与能力”展示三个作用域：作者级、系列级和作品/POV 级。

- 记忆整理员只提交至少有两条独立证据的候选规则。
- 候选必须由作者确认后才进入后续 Agent 上下文。
- 每条规则可以编辑类型、正文和证据，也可以删除。
- 候选、证据和状态会写入当前作品的仓库快照，换电脑后仍可继续审查；只有“已确认”状态才是 Agent 的生效约束。
- 删除会同时更新独立作者档案和当前仓库快照；以前的 Git 历史仍可审查。
- 作者档案可以导入导出，用于换电脑或跨系列复用。

## 7. Git 变更怎么看

内容文件默认使用成熟的 GitHub 风格差异视图：

- 绿色表示新增，红色表示删除；
- 可切换统一视图和左右并排视图；
- 有行号、语法高亮和自动换行；
- `.novel/events/*.jsonl` 默认翻译成任务、评论、Agent、保存等事件摘要，不要求作者阅读一整行 JSON；需要审计时可以切换原始差异。

提交弹窗只暂存并提交勾选的文件，不会 push，也不会夹带未勾选内容。

每个作品可以在“项目设置 → 当前仓库 → Git 提交策略”选择：

- **作者确认后提交**：保留“明确提交”入口，仍然必须由作者逐次确认；
- **仅本地，不提交**：继续显示完整 Git diff，但锁定提交入口，主进程也会拒绝提交调用。该策略写入作品的 `.novel/manifest.json`，重新打开项目或运行验收时不会遗失。

两种策略都不会自动提交或推送。若选择仅本地，普通 Git clone 无法带走未提交作品；换电脑时需要完整复制作品目录，或先由作者修改策略并明确建立检查点。

## 8. 当前仓库在哪里

点击作品标题右侧“作品与仓库”，或进入“项目设置 → 当前仓库”，可以查看：

- 本地绝对路径；
- 当前分支与 HEAD；
- 未提交变更数量；
- Git remote（没有配置时明确显示“仅保存在本机”）；
- “在 Finder 中显示”和“复制路径”。

## 9. 删除任意作者内容、系列作品和整个仓库

### 文件、目录或系列中的单部作品

正文、大纲与剧情、研究资料、人物与世界、已确认决定中的文件和子目录，以及系列仓库中的单部作品，都使用相同的安全流程：

1. 工作台先统计文件数、字数、相关事实、任务、评论和 Agent 历史。
2. 输入文件、目录或作品名称确认。
3. 内容移入仓库外的工作台回收站，Git 显示删除，但不会自动提交。
4. 在“作品与仓库 → 工作台回收站”可以恢复到原位置。

内容区域根目录不能直接删除；系列至少保留一部作品。删除系列中的一部作品只解除它的正文目录，不自动删除系列共享的正典、大纲、研究和决定。

删除文件不会物理抹掉引用它的事实、任务、评论或 Agent 历史，因为这些记录仍有审计价值；工作台会明确列出需要复核的引用。结构化记录采用状态语义：任务取消、评论或路线拒绝/作废、故事事实废弃/恢复、Agent 会话停止，历史事件仍然保留。

### 删除整个仓库

在“作品与仓库”危险区输入完整作品名确认。仓库及该项目专属的工作台回收站/恢复点只会移入 macOS 废纸篓，平台不提供“永久清空废纸篓”。如果没有 Git remote，本机可能是唯一历史副本，因此应先提交并备份。

## 10. 保存、恢复和冲突

- 默认停止输入 5 秒后自动保存；失焦保存默认开启。
- 未保存内容会定期写入仓库外恢复点，不污染 Git。
- 作者缓冲区与磁盘/Agent 同时修改时，工作台进行三方合并。
- 不重叠修改自动合并；同段冲突必须逐段选择作者版、编辑基线或磁盘版。

## 11. 换电脑

1. 在旧电脑明确提交并 push，或完整复制仓库目录。
2. 在新电脑安装并登录自己的通用 Agent。
3. 用工作台打开仓库。
4. 正文、正典、目标、任务、重要评论、Agent 摘要和作品风格快照会重建。

凭据、完整 Agent 日志、临时缓存和未保存恢复点不会随仓库迁移。

## 12. 常见问题

- **保存后为什么 Git 还有变更？** 保存只是把缓冲区写到磁盘；只有明确提交后 Git 才建立版本。
- **Claude Code 为什么不可用？** 工作台会展示安装与登录状态；请先在 Claude Code 自己的客户端完成登录。
- **Observer 的评论为什么过期？** 原文已经变化且无法可靠重定位，工作台不会把旧意见冒充当前意见。
- **为什么不能同时启动两个 Writer 改同一卷？** 工作台主动阻止重叠写入，避免两个 Agent 覆盖彼此。
- **浏览器页面为什么不能写真实仓库？** `dev:web` 明确是 UI 演示；请使用 Electron 桌面窗口。
